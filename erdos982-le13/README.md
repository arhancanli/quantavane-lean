# Erdős #982 for n = 12 (and every 3 ≤ n ≤ 13) in Lean 4

Quantavane, 11 November 2026. Lean v4.33.1, Mathlib as pinned by formal-conjectures `2f91d25`.

**Result.** `E982C.erdos_982_twelve` (in `E982C/Main12.lean`) has exactly the type of formal-conjectures'
`Erdos982.erdos_982 12 _`: every convex 12-gon has a vertex with at least 6 distinct distances to the other vertices.
`E982C.erdos_982_le_thirteen` covers every 3 ≤ n ≤ 13. `MyCheck12.lean` and `test/Statement12.lean` check both
against `FormalConjectures.ErdosProblems.«982»`. Neither uses `sorry`. `#print axioms` gives `propext`,
`Classical.choice`, `Quot.sound` and the `native_decide` axioms of the LRAT checks: ten `E982C.chunk12_j` for n = 12,
plus `gen_4/6/8/10/13_unsat` for the combined theorem. The geometric part (`core_false`, `cuts_ok`) uses only the
first three.

## Why n = 12 needs more than `gen 12 5`

`gen 12 5` (the CNF of rounds 1–2: equal/shorter lengths, at most 5 distances per vertex, the half-plane rule, acute
angles) is satisfiable. It becomes unsatisfiable once one geometric fact is added, together with its 24 dihedral
images. The fact: in a strictly convex polygon with vertices 0..11 in counterclockwise order, the five equalities

    |p8 p5| = |p8 p6|,  |p8 p10| = |p8 p11|,  |p10 p7| = |p10 p8|,  |p11 p4| = |p11 p6|,  |p11 p5| = |p11 p8|

cannot all hold.

## The proof

1. **Angle facts** (`E982C/Angle.lean`). `th p v a b = ∠ (p a) (p v) (p b)`, with three kinds of fact:
   * `T_th`: the angles of a triangle sum to π (Mathlib `angle_add_angle_add_angle_eq_pi`).
   * `E_th`: an isosceles triangle has equal base angles (`angle_eq_angle_of_dist_eq`).
   * `A_th`: if y lies strictly between x and z in the cyclic order seen from v (`betwB`), then
     `∠xvz = ∠xvy + ∠yvz`. The proof uses Mathlib's oriented angles. The polygon's orientation (`sign_oangle_eq`,
     `orient`) gives all three oriented angles sign 1, so they equal the unoriented ones (`oangle_add`,
     `oangle_eq_angle_of_sign_eq_one`). The sum, known modulo 2π, is exact because each angle lies in (0, π).
2. **The certificate** (`E982C/Angle12.lean`, generated by `gen12/gen_angle12.py` from `gen12/core1.cert`).
   `core_false` instantiates 19 T, 47 A and 5 E facts. A `linear_combination` with the certificate's rational
   multipliers gives `th 11 4 10 = 5π/4 + (a nonnegative combination of angles)`. `linarith` then contradicts
   `th ≤ π`. The lemma is stated for the vertices relabelled by any injective `g` that keeps the 47 betweenness
   facts, so one proof covers all 24 images.
3. **The CNF** (`E982C/Cnf12.lean`, Std only). `gen12 = genA12.relabel enc`, where `genA12` is the clause list of
   `gen 12 5` followed by `cuts12.map cutClause`. `cuts12` is the image list `gen12/cuts12_images.json`, written as a
   Lean literal. Each cut clause is the negative literals `¬Eq'(cp o a, cp o b)` of one image. `lake exe dump12`
   writes `gen12` in DIMACS. That output is byte-identical to the CNF the solver refuted (`e12/gen12_cuts.cnf`,
   SHA-256 `173bbef6…c869c`: 41,484 variables, 567,771 clauses).
4. **Soundness of the cuts** (`E982C/Cuts12.lean`). `cuts_dec` (`decide +kernel`) shows that each of the 24 relation
   lists is the image of the base list under a dihedral map `i ↦ s ± i` that keeps the betweenness facts. So
   `cuts_ok` holds: every cut clause is true under `asg p` for a ccw convex 12-gon. With the bridge of `Bridge.lean`
   this gives `genA12_eval`.
5. **Unsatisfiability** (`E982C/Cert12.lean`, `E982C/Split.lean`, `E982C/N12/*.lean`). See below.
6. **Assembly** (`E982C/Main12.lean`). `genA12_unsat` (via `dec_enc`), `ccw12`, then `erdos_982_twelve` via `of_ccw`
   (both orientations), and `erdos_982_le_thirteen` from `erdos_982_le_eleven`, `_twelve` and `_thirteen`.

## The LRAT certificate and its checks

* **Solver.** CaDiCaL 3.0.1, `--lrat=true --binary=true`: UNSAT in 1,355 s CPU (1,516 s wall, 447 MB). The binary
  proof was 1.41 GB with 4,190,173 addition steps. This untrimmed file has been deleted; `lrat/make_12.sh`
  regenerates it.
* **Trim.** `lrat/erdos982_lrat_trim_bin.c` reads binary LRAT through mmap. It follows the same conventions as the
  n = 13 text trimmer and produced identical output on n = 10. It keeps the 2,505,174 lemmas reachable from the
  empty clause (77.7M literals, 211.9M hints) and renumbers them densely, giving `lrat/n12/gen12_full.lrat` (2.04 GB,
  SHA-256 `18a8870a…45319`). Both external checkers accept it against `gen12_cuts.cnf`:
  * drat-trim `lrat-check`: `c VERIFIED` (22.8 s, 92 MB);
  * `lratcheck`: `s VERIFIED UNSAT`, 2,505,174 additions (14.2 s, 635 MB).
* **Why chunks.** Lean holds the `include_str` string, its olean and IR copies, and the parsed proof all in memory.
  The n = 13 file (234 MB) needed 2.2 GB, and a 350 MB chunk needed 5.3 GB. One 2 GB proof cannot be checked under
  6 GB, so `lrat/erdos982_lrat_split.c` cuts the trimmed proof into 10 chunks of about 205 MB.
  * Chunk j < 10 refutes `chunkCNF gen12 S_{j-1} S_j` = `gen12 ∧ S_{j-1} ∧ negCls b S_j`. Here `S_j` lists the
    lemmas of chunks 1..j used later (43,728 to 107,174 clauses). `negCls` says "some clause of `S_j` is false"
    using selector variables from b = 41,484 (b is computed in Lean as `lsTop`).
  * Chunk 10 refutes `gen12 ∧ S_9`.
  * `chunk_sound` / `last_sound` (`Split.lean`) are proved for arbitrary clause lists. So the interface files and
    their parser `parseCls` are untrusted data, and `gen12_unsat` chains the ten results.
  * Every chunk CNF (`lrat/n12/c<j>.cnf`) with its proof (`p<j>.lrat`) is accepted by both lrat-check and lratcheck.
    Each `E982C/N12/C<j>.lean` then checks it with Lean's verified checker (`LRAT.check_sound`, `native_decide`).
    A non-final chunk ends by deriving each unit ¬s_i and then the empty clause.
* The pipeline (split, `Split.lean`, the chunk modules) was first smoke-tested on `gen 10 4` with 3 chunks.

## Build times and memory (this Mac, load about 42, `nice -n 10`)

| step | time | peak RSS |
|---|---|---|
| `E982C.Angle` / `Angle12` (certificate) / `Cuts12` | 12 s / 6 s / 13 s | about 3.3 GB (mostly mmapped Mathlib) |
| `E982C.N12.C1` … `C10` (one `native_decide` LRAT check each) | 18–32 s each, about 4.5 min in all | 3.44–3.95 GB per chunk |
| `Cert12`, `Main12` | 0.4 s, 2.7 s | 0.7 GB, 3.3 GB |
| `lake env lean MyCheck12.lean` | 23 s | 6.0 GB RSS, almost all mmapped .olean pages (footprint 138 MB) |

Lake has no job limit. It would run independent heavy modules in parallel, so the chunk modules form an import
chain (`C<j>` imports `C<j-1>`). Build in stages:

    lake build E982C.Cuts12 && lake build E982C.Cert13 && lake build E982C.N12.C10 && lake build E982C.Main12
    lake env lean MyCheck12.lean

Lake does not track `include_str` inputs. Each chunk and interface module therefore records the SHA-256 of its data
file, and `lrat/make_n12_modules.py` rewrites the modules whenever the data change.
